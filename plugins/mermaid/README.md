# Mermaid Diagrams (renderer plugin)

Renders ` ```mermaid ` fences in chat messages to SVG diagrams. This is the reference
implementation of pi-web-ui's fenced-code renderer mechanism: the plugin owns a language,
the app hands it the fence body, and the plugin returns DOM.

## Install

Compiled artifacts are gitignored in this repo, so install a **built** plugin directory,
never a bare checkout:

```bash
git clone https://github.com/Jensen95/pi-web-ui-plugins
cd pi-web-ui-plugins
npm ci
npm run build:mermaid          # -> plugins/mermaid/client/entry.mjs + client/vendor/

# then either copy the built directory into the pi-web-ui data directory
cp -r plugins/mermaid "<dataDir>/plugins/mermaid"
# or point the CLI at a source that ships built artifacts
pi-web-ui install <owner>/<repo>/plugins/mermaid
```

Refresh the page; the plugin shows up under "Interface plugins" in the top bar / settings
panel. Remove it again with `pi-web-ui uninstall mermaid` or by deleting the directory -
` ```mermaid ` fences then render as ordinary code blocks.

## Engine: local vendor first, CDN fallback

- `client/vendor/mermaid.bundle.mjs` is a self-contained build of the mermaid engine
  (generated by `scripts/build-mermaid-vendor.mjs`). Because it lives inside the plugin
  directory, rendering works **fully offline** once the plugin is installed. It sits under
  `client/` because the plugin's static file service only exposes `/plugins/:id/client/*`.
- If that file is missing - for example a minimal install that copied only `manifest.json`
  and `client/entry.mjs` - the plugin lazily loads the engine from the CDN (esm.sh) instead.
- Offline hosts therefore only need `client/vendor/` present. No configuration is involved.

The engine is fetched on first use, not at load time: a conversation without a mermaid
fence never downloads it.

## How it works

- `manifest.json` declares `renderers: ["mermaid"]` plus `view: false` (no tab of its own).
- `src/client.ts` compiles to `client/entry.mjs`, whose default export is
  `{ renderers: { mermaid: (code, ctx) => HTMLElement | null } }`.
- The app (`web/src/plugin-fence.ts`) keeps a language -> plugin registry. When a message
  contains a ` ```mermaid ` fence it imports this bundle on demand and calls the renderer;
  ordinary chat never downloads anything.
- Diagrams follow the active theme: colors are read from the host's CSS variables, and the
  plugin re-renders on the `pi-web-ui:theme-change` event so a theme switch repaints every
  diagram already on screen. Rendering is serialized, because mermaid's configuration is
  global.
- Rendering happens off-screen in a temporary holder, and the root SVG gets a concrete
  width so wide diagrams scroll instead of shrinking to fit the message column.
- Any failure - unparseable diagram, engine unavailable - rejects the renderer, and the app
  falls back to showing the fence as a plain code block.

## Disabling diagram rendering

Uninstall the plugin (`pi-web-ui uninstall mermaid`) or delete its directory. With no
plugin claiming the language, the app always renders ` ```mermaid ` as a plain code block;
there is no separate setting to turn off.

## Development

```bash
npm run build:mermaid    # compile src/client.ts -> client/entry.mjs, rebuild the vendor bundle
npm run typecheck        # tsc --noEmit over plugins/*/src
npm test                 # tests/unit/mermaid.test.ts covers the pure helpers + the build
```

`index.mjs`, `client/entry.mjs` and `client/vendor/` are generated and gitignored - edit
`src/client.ts` and rebuild. The browser loads `client/entry.mjs` as bare ESM, so the
bundle must stay self-contained: no bare npm specifiers, everything inlined except the
runtime vendor import.

## Writing your own renderer plugin

Mirror this directory: declare `renderers: ["<lang>"]` in `manifest.json` and export
`{ renderers: { "<lang>": (code, ctx) => HTMLElement | null } }` from `client/entry.mjs`.
Returning `null` (or throwing) makes the app fall back to a plain code block. See the
"fenced-code renderer plugins" section of `docs/architecture-plugins.md` in the pi-web-ui
repository.
